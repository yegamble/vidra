9. ALPINE FIX AVAILABILITY (apk policy) — re-queried, not inherited
--------------------------------------------------------------------
The claim "no Alpine fix exists" for the AV1 codec packages needs a reading of what
Alpine v3.24 currently offers. The v0.6.4 and v0.6.5 rounds captured one; this round
captured its own the same way, from the same image source and command shape, so the
three are comparable.

docker pull --platform linux/amd64 mirror.gcr.io/library/alpine:3.24
docker run --rm --platform linux/amd64 mirror.gcr.io/library/alpine:3.24 sh -c \
  'cat /etc/alpine-release; apk --print-arch; apk update >/dev/null && \
   apk policy libssl3 libcrypto3 openssl rav1e rav1e-libs libdovi glib 2>&1'
  exit 0, Alpine 3.24.2, x86_64   -> raw/alpine-3.24-apk-policy.txt
  v3.24/community offers ONLY rav1e / rav1e-libs 0.8.1-r0 and libdovi 3.3.2-r0
  (the versions the image carries), v3.24/main offers glib 2.88.1-r1 and
  openssl/libssl3/libcrypto3 3.5.8-r0.
So no Alpine-packaged fix exists for the AV1 crates as of 2026-09-20, even though
upstream fixes exist for anyhow (1.0.103), crossbeam-epoch (0.9.20) and rand
(0.8.6/0.9.3/0.10.1) — reaching them needs an Alpine update or dropping the codecs.
