# vidra-user v0.6.3

**92 commits since v0.6.2** (`b7520f9` → `7242885`). Image:
`ghcr.io/yegamble/vidra-user:v0.6.3`.

Platform-wide context is in [the platform notes](v0.6.3.md).

## Breaking for builders: Node 26

All three Dockerfile stages are `node:26-alpine` and `package.json` declares
`"node": ">=26"`. Building or running the frontend from source on Node 24 is no
longer supported (the F09 ruling); the published image is unaffected.

## Highlights

**Watch and links.** `/v/{code}` is the canonical watch URL and the address bar
shows the short link rather than the raw UUID; legacy links go straight to the
canonical short code; an imported PeerTube instance's links stay alive. Private
links resolve only after session restoration. The original source survives an
HLS teardown.

**Auth and account security.** "Finish securing your account" — a
provider-only account can set a password and a real email; a provider is
connected from settings rather than auto-linked; the SSO second-factor landing;
instance-named auth screens; verification resend; admin MFA reset; mail-dependent
surfaces say so when the instance cannot send mail; two honesty fixes to the
secure-account card. Cookie refresh is serialized across browser tabs.

**Settings and privacy.** Change your email address with confirmation; password
change with effective session revocation; profile, credentials and account
archive; the discovery opt-out is described as covering playback telemetry;
history controls.

**Moderation and admin surfaces.** The owner is marked and guarded actions say
why they are off; tombstones are distinguished from deactivations and both
account flags get controls; creator-visible block reasons, unblock notices and
ownership transfer; the Word matches page describes the queue it actually shows,
with the flag-time snapshot and triage; mute/block controls on the channel and
profile; `/admin/system` shows the deployment's processes and says why a
component is down, naming the scanner, storage-write and MFA-key components; the
manual media purge says it still deletes when the daily sweep is off; the live
and transcription toggles explain a missing dependency.

**Live.** Termination reason and viewer count in the UI; the watch view polls
during a broadcast; the terminate body is no longer double-encoded.

**Federation.** Remote videos play against the origin; block from the remote
watch view; a federation card; the block control names the actor it blocks; the
threaded mirror renders.

**Messaging.** One E2EE bubble per message rather than one per addressed device;
plaintext history pages without moving the reader; attachment limits aligned
with the shipped 30-file / 100 MiB contract.

**Studio.** Channel-sync failure count and next-attempt time; scheduling
metadata saved before upload finalization; failed batch rows resume without a
duplicate draft; upload recovery failures are retained for retry; chapters
survive a failed initial read; a cancelled upload no longer strands the creator;
analytics no longer shows the previous channel's totals.

**Scan.** Safety-scan rejection copy and upload-capability truth, so the Studio
hides what the instance cannot accept.

**Quality.** A required-control inventory across mobile, theme, keyboard, error
and persistence (register row QLT-02). A session-restore sweep so viewer-scoped
reads wait for the settled session. Server-rendered reads carry a correlation
id. A QoE source switch counts as a new start, so an IPFS watch stops reading
api-proxy. Contract regenerated for the typed OIDC 502s, the storage write
verdict, the degraded component state and caption visibility; the contract guard
now catches HTTP-method drift and is itself under test. The e2e MFA spec hands
out one TOTP code per step (it had been reusing a burned code since the replay
fix landed in core).

**Dependencies.** hls.js 1.7.1 → 1.7.2, @playwright/test 1.62.1 → 1.63.0,
eslint-config-next 16.3.3 → 16.3.4, @types/node 26.4.0 → 26.4.1,
@types/react-dom 19.2.3 → 19.2.7.
