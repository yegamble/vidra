# Vidra v0.6.3 — platform release notes

**Released 2026-09-09.** Previous release: **v0.6.2** (2026-09-04) in all four
repositories.

This is the release that carries the completion campaign's merged work: 74
commits in `vidra-core`, 92 in `vidra-user`, 8 in `vidra-search` and 138 in the
meta repository since v0.6.2. Every claim below is cited to a section of
[`docs/release-readiness.md`](../release-readiness.md) or to a file in this
repository; anything the campaign did not measure is in **Known residuals** at
the bottom rather than left implied.

## Upgrade at a glance

| | v0.6.2 | v0.6.3 |
|---|---|---|
| Core schema | 125 | **144** (19 migrations, `0126`–`0144`) |
| Search schema | 16 | **18** (2 migrations, `0017`–`0018`) |
| Frontend runtime | `node:24-alpine` | **`node:26-alpine`** (`package.json` requires `>=26`) |
| Core/search build | `golang:1.27-alpine` on `alpine:3.24` | unchanged |
| Malware scanning | off by default | **on by default** (`CLAMAV_ADDR` + the `scan` compose profile) |
| App-only rollback | not supported | **supported from v0.6.3 onward** |

Upgrade with `deploy/deploy.sh` unmodified. Its order is load-bearing:
pre-deploy dump (aborts the deploy on failure) → `pull` → the core and search
migrators as **two discrete exit-code-gated steps** → `up -d --no-build` →
health probes. Both ledgers are asserted independently of the migrator, from
the pinned nested checkouts, so a drifted checkout is caught rather than
believed (meta `AGENTS.md` rule 3).

### Accepted compatibility break — one handle namespace (migration 0142)

v0.6.2 binaries running on a v0.6.3+ schema answer **409 `handle_reserved`**
when creating a channel whose handle equals an existing username (and 409 on
the account side for the mirror case) where they used to answer 201. Nothing
crashes and nothing is lost — v0.6.2 already maps SQLSTATE 23505 at both write
sites, so the refusal is the boundary behaving. The break is registered in
`vidra-core`'s `scripts/ci/expected-prev-release-failures.txt`, consulted by the
`schema-compat` lane only when a capability probe says the previous release
predates the migration that caused it; an unregistered failure fails the job and
a registered test that *passes* also fails it, so the entry cannot outlive the
break. Full text: `deploy/README.md` → "Release notes: accepted compat breaks".

### Rollback floor

**App-only rollback is supported from v0.6.3 onward. A v0.6.2 target uses the
restore path.** Before this release, `rollback.sh` could take a site down: `up
-d` starts the `migrate` and `search-migrate` one-shots first (api and search
depend on them with `service_completed_successfully`), and a migrator whose
newest embedded migration sat below the ledger in front of it exited 1, so every
service waiting on it never started. Both migrators now treat a **clean** ledger
above their newest embedded migration as the no-op the policy always said it
was:

```
schema version 135 is newer than this binary's newest migration 125; nothing to apply
```

A **dirty** ledger still fails at any version — dirty means the schema state is
unknown. Each repo carries a `rollback-floor` CI lane that runs the previous
release's *migrator* (not its tests) against this branch's schema, which is the
process `up -d` actually starts; it complements `schema-compat`, which checks
the code half. `restore.sh` gained two preflight refusals that fire **before**
the drop: a dirty dump, and a pinned image whose schema is below the dump's.
Evidence: readiness `## A38 upgrade, rollback and dirty-schema recovery`,
`## A38 rollback floor — migrator no-op, restore preflight`, and
`## A38 rehearsal — rollback floor re-run against the merged fix`.

An app-only rollback across an *incompatible* migration is still restore-then-
rollback; old code cannot read a renamed column.

## Scan by default

Setting `CLAMAV_ADDR` is what turns malware scanning on. There is no separate
enable flag any more: **`MALWARE_SCAN_ENABLED` is deprecated and no longer
read** (boot warns if it is still present; `MALWARE_SCAN_ENABLED=true` with no
`CLAMAV_ADDR` is still a boot refusal).

`env/production.env.example` now ships scanning **on**, pointed at the clamd the
bundled `scan` compose profile starts — and `scan` is in the template's default
`VIDRA_COMPOSE_PROFILES`, because the address and the profile are one decision,
not two. Budget for it: clamd holds the full signature database resident, about
**1.5–2 GiB**.

Three postures, and only three:

- **scanning on** — `CLAMAV_ADDR` set, `scan` profile running (or an external
  clamd's address with `scan` removed).
- **the documented opt-out** — `MALWARE_SCAN_MODE=disabled`, `CLAMAV_ADDR`
  unset, `scan` dropped. The api warns on every boot, writes one
  `system.malware_scan.disabled` audit row per boot, and `/admin/system` reports
  the clamav component `not_configured` with that sentence.
- **neither** — not a posture. The api boots but refuses every ingestion route
  with **503 `scanner_not_configured`**, and `/instance` reports uploads and
  imports unavailable so the Studio hides them.

`MALWARE_SCAN_MODE` decides what happens when a scan cannot *complete*
(unreachable, wedged past `CLAMAV_TIMEOUT`, or answering garbage): `fail-closed`
(default) refuses, `fail-open` publishes and writes one
`content.upload.malware_scan_skipped` audit row per file, `quarantine` parks for
review — with object classes that have no moderation queue (avatars, banners,
playlist covers, caption tracks, account archives) falling back to fail-closed.
An **infected** file is refused in every mode. Scanning covers every
user-supplied file, not just video: uploads, URL imports, channel syncs,
posters, caption tracks, playlist covers, user and channel avatars and banners,
instance branding, DM attachments and account-import archives. Evidence:
readiness `## A28 captions, Whisper and ClamAV lanes` and
`## Scan hardening — default posture, creator copy, full ingestion scope`;
register row **INT-04 PASS**.

**Upgrading an existing env file:** if you had `MALWARE_SCAN_ENABLED=true`,
delete it — `CLAMAV_ADDR` alone keeps scanning on. If you had
`MALWARE_SCAN_ENABLED=false`, delete it and pick a posture; doing neither leaves
the instance refusing uploads.

## New environment keys since v0.6.2

All are optional with the defaults shown, except where noted. Meta template:
`env/production.env.example`; core template: `vidra-core/.env.example`.

| Key | Default | What it decides |
|---|---|---|
| `VIDRA_IMAGE_REGISTRY` | `ghcr.io` | Registry **host[:port]** the three images are pulled from. Only for mirrors: a private/air-gapped registry, or an upgrade rehearsal against locally built images. The owner path and `VIDRA_*_TAG` are unchanged, so the mirror must keep the same repository names. Mirror all three images and every tag you may roll back to. |
| `CLAMAV_ADDR` | `clamav:3310` (template) | Turns scanning on and says where clamd is. Unset + `MALWARE_SCAN_MODE=disabled` is the opt-out. |
| `CLAMAV_TIMEOUT` | `60s` | Bounds one INSTREAM scan (dial + stream + verdict). Must be > 0 when `CLAMAV_ADDR` is set. |
| `MALWARE_SCAN_MODE` | `fail-closed` | `fail-closed` \| `fail-open` \| `quarantine` \| `disabled`. See above. |
| `LIVE_INGEST_CONTROL_URL` | unset (`http://rtmp:8082` for the bundled `media` profile) | Core's only outbound path to the RTMP server. Without it a moderator's termination ends the broadcast and rotates the key but leaves the publisher's socket open writing segments and a recording to disk, and `/admin/system`/`/readyz` have no `live_ingest` component. **Requires `LIVE_INGEST_SECRET`** — the api refuses to boot with a control URL and no secret. |
| `LIVE_RECORDING_RETENTION` | `0` | How long a finished session's `.flv` recording is kept. `0` deletes it when the replay VOD is published. Before this key nothing ever deleted them. |
| `IMPORT_FETCH_TIMEOUT` | `6h` | Total budget for one import download. |
| `IMPORT_FETCH_IDLE_TIMEOUT` | `60s` | Idle budget for one import download — a stalled transfer fails instead of holding a worker. |
| `CHANNEL_SYNC_ENABLED` | `false` | Channel auto-sync master switch. |
| `CHANNEL_SYNC_INTERVAL` | `1h` | Cadence of a healthy sync. |
| `CHANNEL_SYNC_BACKOFF_MAX` | `24h` | Ceiling on the failure backoff. |
| `CDN_PURGE_MAX_ATTEMPTS` | `8` | Purge retry ceiling. |
| `CDN_PURGE_RETRY_BASE` | `1m` | Purge retry base delay. |
| `CDN_PURGE_RETRY_MAX` | `1h` | Purge retry max delay. |
| `AUDIT_LOG_RETENTION` | `9600h` | How long audit rows are kept. |
| `OAUTH_PROVIDERS` | empty | Provider list for OIDC/OAuth login. Provider **secrets** are passed by `env_file`, not inline. |
| `IPFS_HEALTH_PROBE_INTERVAL` | `5m` | Cadence of the mirror health probe that gates redirects. |
| `IPFS_GC_AFTER_UNPIN` | `false` | Whether an unpin is followed by a node GC. |

Changed defaults: `VIDRA_COMPOSE_PROFILES` is now `core frontend scan`;
`VIDRA_{CORE,USER,SEARCH}_TAG` are pinned to `v0.6.3`. Removed:
`MALWARE_SCAN_ENABLED`.

## Authentication and account security

- **TOTP replay is closed.** A used TOTP step is burned (`0134
  user_mfa_last_totp_step`), so the same six digits cannot be presented twice
  inside their window. Evidence: `## Auth hardening — TOTP replay, admin MFA
  reset, mail truth`.
- **Provider-only accounts can set a password and a real email**, behind a
  step-up assertion (`0144 step_up_tokens`), and the step-up survives the
  refresh rotation the redirect causes. Evidence: `## Auth: session-authorised
  set-password and real email for provider accounts` and `## Auth rehearsal —
  set-password, no auto-link, link flow, MFA over SSO on real providers`.
- **No auto-link on a provider email.** An SSO login whose email matches an
  existing local account no longer silently adopts it; linking is an explicit
  action from settings.
- **The second factor is enforced over SSO**, not only over password login.
- **OAuth/OIDC provider secrets move to `env_file`**, so they are not in the
  compose environment. An unreachable IdP now answers a typed **502** rather
  than reading as a crash. Evidence: `## A05 OIDC — login, linking, collision
  and the second factor on a local provider` and `## Auth trust — no auto-link,
  the second factor on SSO, link from settings, provider env_file`.
- **Admin MFA reset**, email change with re-verification (`0129
  email_change_requests`), password change with effective session revocation
  (`0128 sessions_revoked_reason`), and mail-dependent surfaces that say so when
  the instance cannot send mail. Register rows **AUTH-03 / AUTH-05 PASS**;
  **AUTH-04 PASS** for TOTP and for OIDC on a local Dex fixture.

## Moderation, ownership and administration

`0131 users_is_owner` adds a real owner: an admin can no longer demote the
owner, and the **last admin** cannot be removed — both refuse with typed 422s
(`owner_protected`, `last_admin`). Ownership transfer exists. `0130
video_rejections` and `0132 watched_word_match_snapshots` give rejections a
durable reason the creator can see and give the watched-word queue the
flag-time snapshot plus triage. Role changes reach live sessions and a
tombstoned account cannot be reactivated. Register rows **ADM-01 / ADM-02
PASS** (readiness `## A16 …` sections).

## Configuration, health and operations

`0133 process_heartbeats` makes `/admin/system` see the deployment's processes
rather than only the one answering the request, and job correlation ties a
failure to the worker that had it. Live capability is now reported as setting
**AND** ingest capability, so a configured-but-unreachable ingest is a
`503 live_not_configured` instead of a dead player. Settings precedence is
DB > env > Go default across the 116-key registry. Register rows **ADM-03 /
ADM-04 / OPS-01 / OPS-02 PASS** (`## A17 …`, `## A34/A25 …`, `## A35 …`).

## Media delivery, storage and CDN

`0136 video_transcode_generation` makes a same-source re-transcode
generation-addressed, and `0137 cdn_purge_jobs` gives purge a durable queue with
bounded retry (`CDN_PURGE_*`) and an audit trail. The api can serve as a CDN
origin with governing cache headers and constant edge CORS. Purge families now
cover thumbnail/storyboard replacement, account deletion and instance-wide
download revocation. Presigned S3 delivery obeys CORS, expiry and
authorization. Storage gained a boot write probe, typed refusals and key
redaction, and storage migration/copy/verification/abort keeps the GC interlock.
Register rows **STO-01/02/03, INT-09, INT-10 PASS** (`## A32/A33 …`,
`## A33 remediation 1/2`, `## A33 rehearsal …`, `## A24 …`,
`## Storage hardening …`).

## Live

The bundled RTMP plane works: one nginx worker so a moderator's termination
reaches the publisher, a watchdog disconnect, a verified drop, viewer count and
termination reason in the UI, audited ends, recording retention
(`LIVE_RECORDING_RETENTION`), and a watch view that polls during a broadcast
(`0141 live_termination`). Register row **INT-01 PASS** for the bundled ingest
and a passthrough ladder. `## A26 live RTMP …`, `## A26 rehearsal …`,
`## Live hardening …`, `## Live follow-ups …`.

## Federation (ActivityPub)

`0138 federation_social_parity`, `0139 federation_delivery_identity` and `0140
remote_video_comments`. Remote videos **play** against the origin now (the
outbound AS `Video` carries a stream link, `icon` and `duration`, and the
origin's media answers `Access-Control-Allow-Origin: *`); the AP object id is
dereferenceable; blocking is account-scoped as well as instance-scoped; a
blocked instance's `Follow` gets a signed `Reject` delivered while the block
stands; a comment `Create` cancelled inside a block window resumes and arrives
exactly once; the mirrored thread is threaded; and `0142`/`0143` unify the
handle namespace with validator-safe renames. A video no peer was ever sent is
never retracted. Register row **INT-05 PASS** on a two-instance lab.
`## A29 …` (six sections, ending `## A29 rehearsal 4 …`).

## Discovery and search

`0017` retires the co-visitation support counters and `0018` adds the clear-all
indexes. "Clear all" now **deletes** history instead of anonymising it (that was
a k-anonymity floor bypass); the k-floor applies to co-visitation neighbours;
query aggregates and engagement respect retention; and an opt-out means no
attributed collection. Register rows **SRC-01/02/03 PASS**

## Frontend

Node 26 everywhere (images and `engines`). A required-control inventory covering

One E2EE bubble per message rather than one per addressed device (**MSG-03

## Known residuals

Each is one fact, cited. None is fixed by this release.

- **PeerTube migration is not releasable.** **MIG-03 FAIL**; **MIG-01, MIG-02,
  MIG-04, MIG-05, MIG-06 BLOCKED** — every one of them on the same missing
  input: a sanitized source database/filesystem copy the campaign never
  obtained. Copy-mode import also does not re-transcode, so HLS-only source
  content can land as `video_no_media` (finding F02).
- **F08 — the importer CLI is not shipped.** `vidra-core`'s Dockerfile packages
  only `cmd/api`, and release-assets builds the `vidra` CLI, not
  `cmd/peertube-import`; the documented CLI examples require a source build. The
  admin API/worker path is the supported one.
- **AUTH-04 — the selected external identity provider is deferred.** OIDC passed
  against a local Dex fixture, not against the provider an operator would pick.
- **INT-10 — the selected CDN edge is deferred.** Purge, cache headers and CORS
  were proven against an edge *simulator*; clause 4's residual is that there is
  no proxy fallback after a redirect.
- **INT-07 — no real public IPFS publication.** Proven on a private test
  network; IPFS Cluster durability is a residual.
- **INT-05 — federation residuals:** F8 authoring, third-instance thread
  parents, signed fetch, and the MIG-06 identity clause (source identity after
  migration was deliberately not faked). TLS, real hostnames and interoperability
  with PeerTube/Mastodon are unverified.
- **INT-01 — live residuals:** chat, DVR and tips remain SCP-05 scope.
- **AUTH-01, AUTH-02 and PLAY-01 remain UNVERIFIED** in the register at the time
  of this release; they are not claimed by it.
- **The selected object-storage bucket is deferred.** S3 behaviour was proven on
  MinIO, not on the operator's bucket.
